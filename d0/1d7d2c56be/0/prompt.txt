**Load-bearing subtlety — which port the framework needs.** The client's incident-reporting call is `POST events`, and `events`/`outbox`/health are gated with `.RequireHost($"*:{Ports.Internal}")` (8081), while `incidents` queries are gated to `*:{Ports.Public}` (8080):

- `client/src/BusinessIncidentServiceClient.cs:144` → `CreateInvokeMethodRequest(POST, _appId, "events")`
- `service/src/Endpoints/EventEndpoints.cs:53,95,121` → `.RequireHost("*:8081")`

`RequireHost` matches the **Host header**, so the service must be addressed on **:8081** for the framework's write path to route. That's why the template's HTTPEndpoint points at `http://127.0.0.1:8081` even though the compose maps host 8081 → container 8080.

## How the framework/pipeline addresses both services

- **No URL env vars at all.** Both clients use **Dapr service invocation** through the local sidecar. App-ids are hardcoded defaults:
  - `IdempotencyServiceClientOptions.AppId = "idempotency-service"`, optional `DaprHttpEndpoint` (defaults `http://localhost:3500`) — `/Users/robinhultman/dev/intropy/tooling/idempotency-service/client/src/IdempotencyServiceClientOptions.cs`
  - `BusinessIncidentServiceClientOptions.AppId = "business-incident-service"` (no endpoint override at all) — `/Users/robinhultman/dev/intropy/services/business-incident-service/client/src/BusinessIncidentServiceClientOptions.cs`
  - Config sections if bound from `IConfiguration`: `IdempotencyService:*` and `BusinessIncidentService:*`.
- **Resolution is via Dapr `HTTPEndpoint` components**, whose `metadata.name` must equal the app-id:
  - `/Users/robinhultman/dev/intropy/tooling/intropy-templates/extractor/skeleton/local/dapr-components/idempotency-service.yaml` → `baseUrl: http://127.0.0.1:8080`
  - `.../local/dapr-components/business-incident-service.yaml` → `baseUrl: http://127.0.0.1:8081`
- Blocks register both unconditionally: `extractor/skeleton/src/Program.cs.tmpl:30-31` (`AddIdempotencyServiceClient(); AddBusinessIncidentServiceClient();`) — so `sys create` can emit both services without a per-block flag.
- Job sidecar port: `DAPR_HTTP_PORT` default `3500` (`extractor/skeleton/Taskfile.yml.tmpl:14,60`); `task services:up` prints "Idempotency Service → http://localhost:8080, Business Incident Service → http://localhost:8081" (`Taskfile.yml.tmpl:69-77`).
- `intropy-libs-pipeline/src/Idempotency/ServiceCollectionExtensions.cs` only adapts an already-registered `IIdempotencyServiceClient` — no addressing of its own. Same for `src/BusinessIncidents/ExternalBusinessIncidentRouter.cs`.

**⇒ Required declaration ports:** idempotency-service on **8080**, business-incident-service on **8081**. These fit `Service.Container(image, port)`'s container-port == host-port constraint (the incident service listens on both 8080 and 8081, so 8081 works natively; no collision with 8080).

**⚠️ Two gaps for a `ServiceRef`-only scaffold:** `ContainerService` carries **only image + port — no env vars, no sidecar, no dependencies** (ADR 0011 explicitly: "No connectivity contract"). But the idempotency service needs a **daprd sidecar + azurite state store**, and the incident service needs **Postgres (+ migration job) + rabbitmq/azurite + daprd**, plus `DaprComponentsConfig:*` env. Declaring them as bare `ServiceRef` containers starts them but they won't be functional unless the Aspire backend also brings the sidecars/backends (compare the templates' compose, which needs 6 services to do this).
